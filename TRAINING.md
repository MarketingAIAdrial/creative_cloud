# Creative Studio reference review and training

"Training" in this workflow means a reviewed reference library and versioned instructions. It does not mean model fine-tuning or guaranteed permanent memory. Approved guidance must be stored and loaded deliberately for each future job.

The fresh catalog begins empty. Migration does not authorize restoring old examples or generating new ads. Add examples through the review process only after the migration and when requested.

## Add and review inspiration

Start with a small, representative set of digital examples in one flat inspiration folder. Keep private examples and their review records in approved private storage, outside this public repository.

For each example:

1. Record its source and version privately. Inspect the actual content rather than relying on its filename.
2. Describe reusable composition, hierarchy, spacing, typography treatment, image placement and creative ideas. Note what to avoid and any market-specific limits.
3. Leave it unreviewed until a human assigns a classification, rationale and scope. An upload, reaction or prior use does not confer approval.
4. Exclude Neutral examples from generation. Use other examples only within their explicitly approved scope.
5. Record the reviewer and review date. Keep later changes versioned so future jobs can identify the guidance they used.

Inspiration may inform layout across markets. It must never override the target market's approved brand assets, colours, typography, language or copy rules. An example's offer or product claim is not permission to reuse it. Print references are outside the current scope.

## Keep review decisions separate

| Decision | What it establishes |
| --- | --- |
| Example upload | Material is available for inspection; it remains unreviewed. |
| Reference review | Classification and permitted reuse within a recorded scope. |
| Template approval | Explicit permission to use a reviewed template under its approved conditions. |
| Creative approval | Acceptance of a particular creative. |
| Delivery verification | Evidence that validated files were uploaded and imported successfully. |
| Publishing authorization | A separate instruction to publish through the intended advertising platform. |

None of these decisions automatically grants the others. In particular, creative approval does not authorize ad-platform publication.

## Turn feedback into useful guidance

Revision feedback applies to the creative being reviewed. Save it as a durable rule only when the reviewer explicitly requests a wider scope. Record where that rule applies, such as a market, campaign, template or output format, and what it supersedes.

Keep actual review records private. Each record should include:

- Source identity and source version.
- Reviewer and review date.
- Classification or approval decision.
- Reuse rationale and what to avoid.
- Scope and any conditions or exclusions.
- Instruction/reference revision and links to relevant private review records.

If guidance conflicts, apply the approved brand/copy sources and seek resolution for any remaining conflict before generation. Do not promote a single creative's feedback into a universal rule implicitly.

## Prepare a production job

A later explicit production request is required before generating creatives. Before drafting, validate the brief, deliverables, target market, approved source versions, eligible examples and supported generation route. Resolve missing or conflicting information. Do not invent offers, dates, discounts or product claims.

The worker must load the reviewed instruction revision, market documents, eligible examples and brief at job start, and record those versions with the job. Codex reads AGENTS.md in repository context; a hosted worker requires explicit implementation to load and enforce this guidance. Uploading Markdown alone does not connect generation, permissions, scheduling or billing.

A local sign-in or subscription name does not establish hosted image-generation availability. Leave generation unavailable until the actual route is verified. If the intended route is unavailable or exhausted, stop and explain the blocker; do not silently switch to paid API usage, another account/provider or purchased credits.

Setup and migration include no ad generation, model-generation smoke tests or generation-credit spending. Any real generation test requires separate explicit authorization.

## Validate and deliver

Check output content against the brief and approved market rules, and verify the required file format, dimensions and delivery profile. Complete the application's package-integrity checks, authenticated SharePoint upload and importer verification. Record the actual outcome privately and make retries safe against duplicates.

Do not claim success from a queued request or an attempted upload. Report verification failures and keep delivery incomplete until the required evidence exists. Publishing to an advertising platform remains a separate authorized action.
